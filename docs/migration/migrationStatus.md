# migration 상태 정리

## 목표

- 현재 프론트엔드는 `src` 단일 구조로 운영한다.
- 과거 `v1`/`v2` 분리 이식은 완료되었고, 런타임 기준 `v1` 의존은 제거되었다.
- 이후 작업은 `src` 기준으로만 진행한다.

---

## 운영 원칙

1. 기능 추가/수정은 모두 `src` 아래에서만 진행한다.
2. 레거시 비교가 필요하면 문서/깃 히스토리 기준으로 확인한다.
3. 기능별 디렉토리 구조와 네이밍 규칙을 유지한다.

---

## 참조 방식

### 1) 기본

- 런타임 기준 alias `@`는 `src`를 바라본다.
- 즉, `@/views/...`는 현재 서비스 루트 기준으로 해석된다.

### 2) 현재 상태

- 런타임 코드에서 `v1` import는 없다.
- 엔트리, alias, API, 뷰, 컴포넌트는 모두 `src` 기준으로 정리되었다.

---

## 이식 단위 전략

1. 페이지 단위로 진행한다. (예: `auth` -> `main` -> `video-player`)
2. 각 페이지마다 아래 순서로 이동한다.
   - view
   - 직접 사용하는 컴포넌트
   - API / store / entity
   - 스타일(공통 우선)
3. 이식 완료 시 `v1` 참조를 제거하고 `v2` 내부 참조로 닫는다.

---

## 현재 상태 기준 분류

### 이식 완료 범위

- `auth`
- `main`
- `video-player`
- `channel`
- `studio`
- `together`
- `message`
- `playlist`

### 문서 보관 위치

- 이식 관련 문서는 `docs/migration/`에 둔다.
- 임시 점검 로그도 실행 코드가 아닌 `docs/` 또는 `refactor-pages/` 아래에서만 관리한다.
